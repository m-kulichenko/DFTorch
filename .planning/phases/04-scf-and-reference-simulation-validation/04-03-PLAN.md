## Scope boundary — read before implementing

The shell-resolved Coulomb matrix is `(n_shells_total, n_shells_total)`; for Eu-N that is
`(6, 6)`. `_energy.energy` and `SCFx` consume a `(Nats, Nats)` Coulomb matrix together with
per-atom charges of shape `(Nats,)`. Making the shell-resolved matrix *consumable* therefore
requires shell-resolved charges threaded through the whole SCF loop — which is exactly the
self-consistent SCF work D-11 defers out of this phase.

So this plan does three things and deliberately does not do a fourth:

1. Validates that the shell-resolved data structures carry the f shell with correct values.
2. Gates the Coulomb-path Hubbard U selection on `magnetic_hubbard_ldep` and builds the
   shell-resolved matrix *alongside* — never instead of — the per-atom `structure.C`.
3. Refuses to build a shell-resolved Coulomb matrix for a system containing a 16-orbital atom.
4. **Does not** implement the seven missing f angular blocks (s-f, f-s, p-f, f-p, d-f, f-d,
   f-f) of the shell-resolved Coulomb matrix. That is blocked by (not merely harder than) the
   deferred SCF work, since there is no consumer that could validate the values. This is a
   flagged, developer-visible boundary, not a silent omission — see the plan set's return
   notes.
