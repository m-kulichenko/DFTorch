<objective>
Add the loud refusal for genuinely incompatible parameter sets (REG-05), finish the per-pair
radial lookup by giving every remaining reader of the shared grid a written disposition
(REG-06), and pin the full public import surface so REG-03 is checked rather than assumed.

Purpose: plan 05-01 made the live single-system lookup per-pair, which makes a mixed-length
load correct. Decision D-01 keeps the guard anyway, for the case the per-pair fix does not
address: two parameter sets whose radial grids are sampled at different *steps* are not merely
awkward to index, they are physically different tabulations, and silently combining them is the
factor-of-two error D-01 describes. The guard's one real trap is that the obvious
implementation — compare grid lengths — passes the exact case it exists to catch, so this plan
states the comparison explicitly and tests the benign case as hard as the hazardous one.

Output: a named refusal in the SKF loader, a disposition record for every grid consumer, a
corrected unit docstring, and a full-surface public API assertion.
</objective>

**Why the guard still matters after 05-01.** Plan 05-01 made each pair index its own grid row,
so a mixed-*length* load now interpolates correctly. It did not make a mixed-*step* load
correct, and cannot: two tabulations sampled at different steps carry different information at
different radii, and combining them in one calculation is a parameter-set error the user should
be told about rather than have silently accommodated. That is why D-01 keeps both halves.
