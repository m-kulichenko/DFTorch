<objective>
Port the checks that `src/dftorch/script.py` performs and nothing else does into `tests/`, then
delete the file — decision D-03.

Purpose: 1656 lines of pre-pytest validation currently ship inside the runtime package and CI
never invokes them. The reason this is a port rather than a deletion is one specific property:
`parse_expected_homonuclear_metadata` builds its expectations by re-parsing the SKF header
independently, so it never uses the production parser to check the production parser. The
72-test pytest suite does not have that property anywhere. Losing it would make every SKF
metadata test self-confirming.

Output: a written disposition for every check function in the file, a pytest module carrying the
independent-oracle checks, and the file gone.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.skf` file text -> ported oracle -> expected metadata | Local files the user chose, read read-only as text. Trusted input. |
| production parser vs independent oracle | Not a security boundary, but the integrity boundary this plan exists to preserve: two paths to the same number, so neither can confirm itself. |

No new attack surface. The one genuinely security-relevant change is a reduction: deleting
`script.py` removes `ensure_fake_dftorch_package` and `load_dftorch_module`, which construct a
synthetic package directory and import modules by filesystem path.
