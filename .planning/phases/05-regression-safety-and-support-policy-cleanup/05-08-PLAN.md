this phase can reach.

number captured in the same session as the change it guards. That family of gate is good at

asks for.

<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 1: Human sign-off on the Phase 5 records and the unchanged-behaviour claim</name>

  <what-built>
    Phase 5 delivered, across seven plans:

    - **Per-pair radial grid lookup (REG-06, D-01).** Each element pair now finds its spline
      knot against its own grid row rather than against the longest grid in the directory.
      Existing single-grid results are asserted bit-identical. A measurement made during
      planning also settled a long-standing contradiction: `_ml_sk.py`'s docstring claimed the
      grid and the pair distances were in different units; both are in Angstrom, and the
      docstring was corrected against the measurement.
    - **Mixed-step refusal (REG-05).** An `SKFPATH` whose files declare different radial grid
      steps now raises a named error listing the offending files and both steps. Same-step,
      different-length directories are accepted, because `3ob-3-1` ships exactly that.
    - **Verbose flag (D-02).** One `dftorch_params` key suppresses library status chatter. The
      default is unchanged and byte-identical output is asserted by a test. Genuine failure and
      non-convergence warnings are deliberately not suppressible.
    - **`script.py` removed (D-03).** Its independent-oracle SKF header checks were ported to
      pytest first; the port's independence is checked by source inspection rather than assumed.
    - **Orbital-count audit (D-04, CLN-03).** Every hardcoded 1/4/9/16 site swept, inventoried
      and dispositioned; refusals added where f is genuinely unsupported.
    - **Documentation (CLN-01, CLN-02, CLN-04).** A basis metadata map with cross-consistency
      tests, a prototype-branch record, and an f support status matrix.
    - **REG-02.** Settled by explicit developer decision in plan 05-02, because the tutorial
      notebook cannot run here: its first computational cell reads a `COORD.pdb` that is not in
      the repository, one cell hardcodes a CUDA device, and no notebook tooling is installed.
  </what-built>

  <how-to-verify>
    Roughly twenty minutes. Four things, in order of how much they would cost to get wrong.

    **1. Read one inventory row at random from each of the four records and ask whether it tells
    you anything.** The records are `docs/ORBITAL-COUNT-INVENTORY.md`,
    `docs/LIBRARY-OUTPUT-INVENTORY.md`, `docs/SCRIPT-PY-PORT-INVENTORY.md` and
    `docs/RADIAL-GRID-CONSUMERS.md`. Every automated gate in this phase checks that these have
    the right number of rows. None checks that a row says anything. Specifically: does a
    `dropped` row name the test that covers it, or does it just say the check was redundant?
    Does an `unreachable` row say how unreachability was established, or does it assert it?

    **2. Trigger one refusal yourself and read the message.** Pick any `guarded` row from
    `docs/ORBITAL-COUNT-INVENTORY.md`, find the test in `tests/test_orbital_count_guards.py`
    that reaches it, and run it with `-v` so you see the message. Ask whether a user who hit
    that message would know what to do next, or only that something was refused.

    **3. Check the unchanged-behaviour claim from outside the tests.** Run
    `uv run pytest -q` and confirm the count is at or above the entering baseline of 72. Then
    run `git log --oneline` over the phase's commits and confirm plan 05-02's baseline commit
    precedes the commits from plans 05-01, 05-04, 05-05 and 05-06. A baseline captured after the
    changes it guards proves nothing, and the ordering is the only evidence of that.

    **4. Read `docs/F-SUPPORT-STATUS.md`'s known-open-issues section and its REG-02 ledger row.**
    Confirm the CH4 SCF non-convergence is recorded and attributed to Phase 6, and that REG-02's
    row states its narrowing rather than reading as an unqualified pass.

    Two things this checkpoint deliberately does NOT ask you to do: fix the CH4 SCF
    non-convergence, which is Phase 6 territory under decision D-13 and is the one open
    `.planning/WINDOWS.md` entry blocking `/gsd-ship`; and re-derive any physics, since Phase 5
    changed none.
  </how-to-verify>
