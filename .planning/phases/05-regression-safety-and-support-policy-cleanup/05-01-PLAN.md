<objective>
Close the shared-radial-grid defect (REG-06, decision D-01) by giving every element pair its
own radial grid row for the spline knot lookup — and prove, before touching the lookup, that the
change is behaviour-preserving for every parameter set that exists today.

Purpose: `_bond_integral.get_skf_tensors` already stores each pair's own grid in `R_tensor`, but
exports a single global `R_orb` chosen as the longest grid seen. `_h0ands` derives the
interpolation knot from that one array for every pair type, so a pair whose real grid differs is
evaluated against another pair's ruler. All nine `tests/f_orbital_data` fixtures happen to share
a grid, so the defect is currently inert — which is exactly why it needs a characterization test
first: there is no observed failure to work backwards from, only a model of one.

Output: a characterization test module pinning today's knot arithmetic and effective cutoffs, a
monotonic `R_tensor` with a companion length vector, and a per-pair knot lookup in the live
single-system H0/S path.
</objective>

**The unit question is settled, and it settles it the safe way.** `_ml_sk.py:437-450` claims
`R_orb` is Angstrom while `dR_mskd` is Bohr, and that `searchsorted` therefore compares
mixed-unit arrays. That claim is wrong, and the same file contradicts it eleven lines later:
`_ml_sk.py:522` annotates `dR_mskd` as Angstrom. The measurement above confirms line 522 — both
sides of the comparison are Angstrom, and the lookup is unit-consistent. Sanity check on the
arithmetic: a CH4 C-H distance of `1.05668` A over a `0.0105835442` A step gives `idx = 98`, and
`R[98] = 1.04777` A, which is the correct physical knot. Under the docstring's Bohr theory the
knot would sit at roughly twice the true separation and CH4 would not produce a sane energy.

The practical consequence: **the per-pair rewrite does not need to reason about units at all.**
Correcting the `_ml_sk.py` docstring is scoped to plan 05-04, which owns that file.

**Closed-form index (for reference, not required).** Because each grid is
`R[k] = (k+1) * h`, `searchsorted(R, dR, right=True) - 1` equals `floor(dR / h) - 1`. Verified:
`floor(1.05668 / 0.0105835442) - 1 = 99 - 1 = 98`. Do NOT implement the closed form — it can
disagree with `searchsorted` by one when a distance lands exactly on a knot. Use the loop
described in Task 2.
