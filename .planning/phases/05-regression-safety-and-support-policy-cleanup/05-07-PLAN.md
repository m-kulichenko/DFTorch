<objective>
Close the three documentation requirements — prototype branches (CLN-01), basis metadata
centralized enough for troubleshooting (CLN-02), and the f support status matrix (CLN-04) — and
back each with whatever machine check it honestly admits.

Purpose: these are documents, not behaviours, and it would be easy to satisfy them with prose
nobody can falsify. Two of the three admit a real gate. Basis metadata is duplicated across four
sites with two different conventions, so a cross-consistency test turns "centralized enough"
into something that fails when it stops being true. The support matrix is cross-checkable
against the named exception classes, so an exception added later without a matrix row fails the
suite. Prototype-branch documentation admits only a presence check, and this plan says so
rather than pretending otherwise.

Output: three documents and a test module that checks the two checkable claims.
</objective>
