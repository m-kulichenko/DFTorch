<objective>
Make the charge loop actually use per-orbital-group charges, so that europium's f electrons are
charged at the f group's own electron-repulsion strength rather than at the s group's.

**Plain-language orientation.** During the repeat-until-settled loop, the code has to answer "how
much charge is sitting on each part of the molecule, and what does it cost to put it there?" Today
it answers per **atom**: one charge number for europium, one for nitrogen, and one repulsion
strength each. The finer answer is per **orbital group** - separately for the s, p, d and f groups
of each atom. This project calls that *shell-resolved*; "shell" is just its word for one of those
groups.

The reason it matters is a concrete measured defect. `Constants.py:232` reads
`self.U = torch.nn.Parameter(US, ...)`: the per-atom repulsion strength is the **s** group's value,
unconditionally, for every element. For nitrogen that is harmless - its s, p and d values are all
13.33 eV, identical. For europium they are not:

| group | repulsion strength (eV) | europium's electrons there |
|---|---|---|
| s | 5.71 | 2 |
| p | 5.17 | 0 |
| d | 6.80 | 0 |
| **f** | **13.61** | **7** |

So the code charges europium 5.71 eV per unit of charge while seven of its nine outer electrons sit
in a group whose real cost is 13.61 eV - 2.4 times more. A human ruling of 2026-08-04
(`06-RESEARCH.md`, "Scope rulings", item 3) put this in Phase 6 scope and named the shell-resolved
work as its remedy. The measured size of the effect at large separation: leftover charge transfer
moves from 0.29 electrons to 0.20 electrons, about 30 percent, on a real observable.

**What has to be built.** Not "wire up something that exists". The per-orbital-group charge
machinery exists only inside the **open-shell** routine `scf_x_os` (`_scf.py:699-739`), which Phase 4
decision D-12 makes refuse any f system outright. Searching the closed-shell routine `SCFx`
(`_scf.py:158-556`) for shell-resolved symbols returns nothing. So this plan builds a new
per-orbital-group charge path inside the closed-shell loop, using the existing shell metadata that
Phase 4 built and never consumed.

Purpose: this is requirement SCC-03 - "the shell-resolved f plumbing validated but unconsumed in
Phase 4 is actually consumed by the self-consistent path". Plan 06-02 supplied the matrix; this plan
supplies the consumer.

Output: a closed-shell charge loop that can run at either resolution, selected by the parameter key
that already exists for it, with the per-atom answer still available to every existing caller.
</objective>

## The assumption delta this plan carries

Plan 06-01 flagged it and this is where it lands: **per-atom charge stops being the only kind of
charge.** Before this plan, `structure.q` was *the* charge. After it, there are two resolutions and
`structure.q` is one of them.

The mitigation is deliberate and is a hard requirement of this plan: **`structure.q` keeps being
populated in both modes**, derived in shell-resolved mode by summing the per-orbital-group numbers
over each atom. The dipole term, the reported charges, plan 06-05's graph and every existing test
read it. Nothing downstream is asked to learn a new attribute in order to keep working; the new
`structure.q_sr` is purely additive.

## Design decision - where the finer charges enter the loop

The loop's inner call is `calc_q` (`_xl_tools.py:21`), and it already works entirely at the level of
individual orbitals: it takes an orbital-length repulsion strength, an orbital-length charge and an
orbital-length potential, and builds the Hamiltonian correction from them. In per-atom mode the
caller hands it three arrays gathered from atoms out to orbitals. **In per-orbital-group mode the
caller hands it the same three arrays gathered from groups out to orbitals instead.** No change to
`calc_q` is needed at all.

The only per-atom step left inside `calc_q` is the final tally that scatters orbital populations back
into per-atom charges. In shell-resolved mode the loop ignores that return value and does its own
tally into groups, from the density matrix `calc_q` already returns. This costs one extra scatter per
pass and keeps `calc_q` untouched, which is worth far more than the saving.

Reversibility: **reversible**. The new behaviour is a branch inside one function, entered only when
the caller passes shell metadata that defaults to absent.

## Design decision - the electron-repulsion energy

`_energy.energy` computes several things from per-atom quantities: the band energy, the dipole term,
the entropy and the electron-repulsion energy. Only the last of those changes resolution.

**Chosen: three keyword-only optional arguments** on `energy()` - the shell-resolved matrix, the
shell-resolved charges and the shell-resolved strengths - all defaulting to absent. When all three
are supplied, the repulsion energy is computed from them; everything else keeps using the per-atom
quantities exactly as before. Every existing caller is unaffected because it passes none of them.

Rejected: a separate `energy_sr` function (duplicates the band, dipole and entropy arithmetic, which
is where drift between two copies would silently appear), and re-using the existing `C` and `q`
arguments with a length check (an argument whose meaning depends on its length is exactly the kind of
ambiguity `_select_coulomb_hubbard`'s docstring already argues against).

Reversibility: **reversible**. Three defaulted keyword arguments; deleting them restores the previous
signature.

## Design decision - refusing rather than falling back

`ESDriver.forward` builds the shell-resolved matrix **only** in the non-PME branch (from line 342).
Under `COUL_METHOD` set to PME, `structure.C_sr` stays `None`. Likewise the third-order DFTB3
correction is per-atom only.

So a shell-resolved request in either of those configurations has no matrix to use. **It must fail
loudly**, naming the configuration, rather than quietly computing the per-atom answer and presenting
it as the finer one - that is the codebase's established "fail loudly, never silently zero" pattern.

Use a plain `NotImplementedError`, **not** a new `F*` class. Two reasons: the gap is not about f
orbitals at all (no shell-resolved reciprocal-space counterpart exists for any element), and Phase 5
set exactly this precedent when it resolved the batched reciprocal-space apology with a plain
`NotImplementedError` rather than extending the four-name f taxonomy.

## Trust Boundaries

Unchanged in kind from plans 06-01 and 06-02: a local scientific library, no network, no
authentication, no untrusted input, no user data. The boundary that matters is between a number the
code produces and a human who believes it. This plan adds one more: **between two resolutions of the
same quantity**, where a caller can hold one and believe it is the other.

| Boundary | Description |
|---|---|
| per-atom charge <-> per-group charge | Two arrays of different lengths describing the same physical state. Confusing them produces a plausible answer of the wrong resolution. |
| shell-resolved request -> available machinery | Under PME, and under third-order DFTB3, the finer matrix does not exist. A request there could be served by the coarser one without anyone noticing. |
| loop -> energy report | The loop and `energy()` each compute an electron-repulsion energy. If they use different resolutions, the reported total disagrees with the converged one. |
