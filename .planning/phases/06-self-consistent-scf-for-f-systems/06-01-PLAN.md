<objective>
Make the self-consistent charge loop actually finish for the europium-nitrogen test molecule,
and give the loop an honest, machine-readable way to say whether it finished or gave up.

**Plain-language orientation.** This project computes the energy of molecules with a fast
approximate quantum-chemistry method. Part of that calculation is a repeat-until-settled loop:
guess how the electrons are spread across the atoms, recompute, compare, repeat. "Converged"
means the change from one pass to the next fell below a tolerance. Today, for the Eu-N molecule,
that loop runs away at 9 of the 21 atom-to-atom distances tested - electrons pile entirely onto
one atom and the energy comes back at +198 eV against a true scale near -17 eV. For scale: a
typical chemical bond is worth 2-5 eV, so +198 eV is not a small error, it is nonsense.

The cause is already known and is not the f orbitals. It is a convergence-speedup routine called
the **Krylov accelerator** (`kernel_update_lr`), which engages after 10 passes. With it switched
off, all 21 distances settle, and at the 12 distances where the accelerator did work the two runs
agree on the energy to better than one millionth of an eV - so it was never finding a different
answer, it was failing to find the answer the plain mixer finds reliably. That evidence is rated
HIGH confidence in `06-RESEARCH.md` and it generalises: 16 unrelated two-atom molecules over 61
distances each all settled with the accelerator off.

A human ruling on 2026-08-04 (`06-RESEARCH.md` section "Scope rulings") **defers repairing the
accelerator to a later phase**. Phase 6 switches it off and proceeds.

Purpose: this is the tracer slice - the thinnest real path that touches every layer this phase
will modify (the solver, the driver, the result object, the test suite), wired end to end and
proven before any of the wider shell-resolved work begins. If the architecture is wrong, it is
wrong after one commit rather than after ten.

Output: a loop that settles at 2.655 A, a convergence result a caller can read, and a new test
module that proves both.
</objective>

### Discretionary choice 1 - which of the four loops gets the returned result

`_scf.py` holds four repeat-until-settled loops: `SCFx` (line 158, closed-shell single molecule -
the one the f path uses), `scf_x_os` (line 557, open-shell), `SCFx_batch` (line 977, many molecules
at once) and `delta_scf_x_os` (line 1233, excited states). All four carry the same
`print("Did not converge")` line.

**Chosen: all four.** Reasons, in order of weight:

1. Each of the four has **exactly one call site** in production code - `ESDriver.py:678`, `:535`,
   `:1757` and `:607` respectively - so the "positional tuple churn" the context document warns
   about is four small edits, not an open-ended blast radius. This was checked, not assumed; the
   executor re-checks it in task 2.
2. `06-CONTEXT.md` rates this change **costly to reverse** and asks for "a shape that can be
   extended once rather than repeatedly". Doing one loop now and three later is exactly the
   repeated extension that instruction rules out.
3. Leaving three loops printing while one returns teaches a future reader that a printed line is a
   trustworthy signal. `06-CONTEXT.md` records "fail loudly, never silently zero" as this
   codebase's established pattern, and names this one place as where it is currently violated.

### Discretionary choice 2 - the shape of the returned result

**Chosen: one extra element on the end of the existing return tuple, a plain Python `int`, unpacked
into `structure.scf_iter_count`.**

- It is exactly what the user asked for and named a precedent for: scipy's iterative solvers return
  an `info` value beside the answer - a positive count on success, a sentinel on failure. A boolean
  would throw away the count and is explicitly not what was asked for.
- The tuple grows **once**. After that, `structure` is the extensible surface: any later diagnostic
  (final residual, final energy change) becomes another attribute, with no second change to the
  return arity. That is the "extend once rather than repeatedly" the context document asks for.
- A dataclass or `NamedTuple` wrapping all 15 values was rejected: it rewrites all four call sites
  into attribute access rather than adding to them, which is a larger reversal to undo, and it does
  not make the count any easier to read than `structure.scf_iter_count`.

**Reversibility: costly, not one-way.** Undoing it means deleting one element from four return
statements and four unpack sites - mechanical, and every site is named in this plan. It is not
one-way because no data is destroyed and no external contract is published, so no
`checkpoint:decision` gate is inserted before it.

### Discretionary choice 3 - where the Krylov switch-off lives

Three options were weighed:

- **(a) Change the default in `_scf.py`** (`dftorch_params.get("KRYLOV_START", 10)`). Rejected:
  it changes the numerical path for every molecule this library computes, including the f-free
  regression baselines Phase 5 measured. The project's stated core value is f-orbital support
  "without changing numerical results for existing simple-format calculations".
- **(b) Require every caller to pass the key.** Rejected: then requirement SCC-01 - "f-containing
  systems run a true self-consistent charge loop to convergence" - would only be true for a caller
  who knows a magic key. That is not a supported system, it is a workaround.
- **(c, chosen) Switch it off inside the driver, for f-containing systems only, and only when the
  caller has not set the key themselves.** This is the narrowest change that makes SCC-01 true for
  an ordinary caller. By construction it cannot move a single f-free number, because the branch is
  never entered for an f-free molecule. It is one small function to delete when the accelerator is
  repaired in a later phase.

Reversibility: **easy**. One named helper, one call site, one attribute.

## Assumption-delta disposition

The detector flagged this phase on a single weak signal: the word "also" in a ROADMAP prose note
("Also settled: the convergence criterion this phase must assert against already exists"). That is a
prose connective joining two sentences, not a singular-to-plural architectural transition.
**Disposed: not an assumption delta.** No identity-model question is raised.

The genuine assumption delta in this phase is recorded instead, for plan 06-03 to carry: **per-atom
charge stops being the only kind of charge.** Once shell-resolved charge lands (one number per
orbital group per atom, rather than one number per atom), `structure.q` becomes one case among two,
and every consumer that reads it has to be clear about which it wants. Plan 06-03 keeps
`structure.q` populated in both modes precisely so this delta does not break existing callers.

## Trust Boundaries

This is a local scientific-computing library. It has no network surface, no authentication, no
untrusted input, no user data and no multi-tenant state. The web-application threat categories do
not apply and are not padded in here. The real boundary is **between a number the code produces and
a human who believes it**, and every threat below is a way for a wrong number to cross that boundary
wearing the clothes of a right one.

| Boundary | Description |
|---|---|
| solver -> caller | `SCFx` hands back energies and charges. Today a caller cannot tell a settled answer from an abandoned one except by reading printed text. |
| driver -> driver, across calls | One `ESDriver` object is reused across many molecules. A setting written into its parameter dictionary by one molecule is still there for the next. |
| this phase -> later phases | Any number frozen into a test now becomes a fact later phases must not contradict, even if it was produced by a bug. |
