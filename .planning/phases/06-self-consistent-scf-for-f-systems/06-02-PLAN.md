<objective>
Build the seven missing angular blocks of the per-orbital-group electron-repulsion matrix, so that a
molecule containing an f-shell element gets a complete matrix instead of a refusal.

**Plain-language orientation.** Electrons repel each other. This method models that with a matrix
whose entries say how strongly a unit of charge sitting on one atom pushes on a unit of charge
sitting on another. There are two resolutions available. The **per-atom** version tracks one number
per atom - simple, and what the code uses today. The **per-orbital-group** version, which this
project calls *shell-resolved*, tracks one number per orbital group per atom: separately for the
s group, the p group, the d group and the f group. "Shell" here just means one of those groups.

Why it matters concretely, and this is the reason the work is in scope: the per-atom version charges
every element the repulsion strength (the *Hubbard U*) of its **s** group, unconditionally
(`Constants.py:232`). For nitrogen that is harmless because its s, p and d values are all identical
at 13.33 eV. For europium they are not: s is 5.71 eV but f is 13.61 eV - **2.4 times larger** - and
**seven of europium's nine outer electrons live in the f group**. So the code currently charges
europium's electrons about two and a half times too little for being crowded together. Measured
consequence at large separation: the leftover charge transfer moves from 0.29 electrons to 0.20
electrons when the correct value is used - a 30 percent change on a real observable. A human ruling
of 2026-08-04 put this work in scope for Phase 6 and named the shell-resolved matrix as its remedy.

**What is actually missing.** The builder writes one block per ordered pair of orbital groups: s-s,
s-p, p-s, p-p, s-d, d-s, p-d, d-p, d-d - nine of a possible sixteen. The seven involving f are
absent. But the gap is worse than "seven blocks missing", and this is the finding the plan turns
on: the six existing **off-diagonal** blocks select their pairs by testing each atom's orbital range
against the values 1, 2 and 3 only. A 16-orbital f atom has range 4, so it matches none of those
tests and falls straight through. The recorded evidence is in
`tests/test_shell_resolved_u.py:503`: before the refusal was added, a europium-nitrogen molecule
came back with row sums `[0.473581, 0, 0, 0, 0.473581, 0]` - finite, correctly shaped, and zero in
every row except the two s rows, because only the s-s block (which has no mask at all) had filled.

Purpose: this is the expansion task that turns the proven tracer path into a complete matrix, and it
is the precondition for plan 06-03 consuming per-orbital-group charges in the charge loop.

Output: a complete 16-block builder, a new test module that validates it by derived identity rather
than by frozen numbers, and a support policy that says what the code now does.
</objective>

## Why this is in scope at all - the conditional is resolved

`06-CONTEXT.md` decision D-6.06 made this work **conditional on diagnosis**: build it only if the
coarse per-atom charge description turned out to be the cause of the runaway charge loop. The
diagnosis then landed. The cause was the Krylov convergence accelerator, not the charge description
(`06-RESEARCH.md`, HIGH confidence, 21 of 21 separations settle with the accelerator off).

That would have closed D-6.06 the other way - except that a human made a scope ruling on 2026-08-04
(`06-RESEARCH.md` section "Scope rulings", item 3) that settles the condition explicitly:

> **Hubbard-U shell selection - in scope for Phase 6.** The s-shell/f-shell discrepancy
> (`U_s = 0.21` vs `U_f = 0.50` Ha for Eu) is to be addressed by the shell-resolved Coulomb work in
> this phase, which is therefore confirmed as Phase 6 scope rather than conditional.

So the justification for this work is **quality of the answer**, not convergence. It is not being
built to fix a crash. That distinction matters for how it is validated: no test in this plan may
claim that the f blocks made anything converge.

`06-RESEARCH.md`'s own "Validation Architecture" table still carries "only if D-6.06 fires" markers
on the SCC-02 and SCC-03 rows. Those markers predate the ruling and are resolved to in-scope.

## Design decision - how the blocks are selected

The nine existing blocks each build a boolean mask by adding together named combinations, for
example the s-p block uses `pair_mask_HX + pair_mask_XX + pair_mask_HY + pair_mask_YY +
pair_mask_XY + pair_mask_YX`, where H means an atom with s only, X means s+p, and Y means s+p+d.
Adding f means a fourth class and six more named combinations per block - 16 named masks in total,
enumerated by hand, in nine places.

**Chosen instead: one uniform rule.** A block for the ordered orbital-group pair (l_i, l_j) applies
to exactly those neighbour pairs where atom I actually carries group l_i and atom J actually carries
group l_j. In this codebase's encoding an atom's `max_ang` is 1 for s-only, 2 for s+p, 3 for s+p+d
and 4 for s+p+d+f, and the groups are numbered 0 for s, 1 for p, 2 for d and 3 for f. So the rule is

> mask(l_i, l_j) = (max_ang_I > l_i) AND (max_ang_J > l_j)

This was checked by hand against all nine existing blocks and reproduces every one of them exactly,
including the unmasked s-s case:

| block | current mask | uniform rule gives |
|---|---|---|
| s-s | no mask (all pairs) | `max_ang_I > 0` and `max_ang_J > 0` - always true, so all pairs |
| s-p | HX + XX + HY + YY + XY + YX | J in {X, Y} - the same six combinations |
| p-s | XH + XX + YH + YY + XY + YX | I in {X, Y} - the same six |
| p-p | XX + YY + XY + YX | I and J both in {X, Y} - the same four |
| s-d | HY + XY + YY | J = Y - the same three |
| d-s | YH + YX + YY | I = Y - the same three |
| p-d | XY + YY | I in {X, Y} and J = Y - the same two |
| d-p | YX + YY | I = Y and J in {X, Y} - the same two |
| d-d | YY | I = J = Y - the same one |

Reversibility: **easy**. The rule is local to one function and the nine-block behaviour it replaces
is fully specified by the table above.

## Design decision - what happens to the refusal

`FShellResolvedCoulombUnsupportedError` exists precisely because an incomplete matrix looks fine: it
is finite, correctly shaped, and wrong only in that some rows are zero, and zero is a legal-looking
repulsion value. Once the seven blocks land, that reason is gone.

**Chosen: retire the refusal, keep the class.** Concretely: delete the guard function
`_require_no_f_shell_resolved_coulomb` and the call that opens
`ewald_real_space_vectorized_sr`, but leave the class `FShellResolvedCoulombUnsupportedError`
defined in `_slater_koster_pair.py` with its docstring rewritten to record that it is retired, by
what, and what would bring it back.

Why keep a class nothing raises: Phase 5 pinned the f exception taxonomy at exactly four names via
`tests/test_orbital_count_guards.py::test_no_new_f_exception_class_was_defined`, deliberately, so
that the whole f support policy reads as one reviewable list. Deleting a name breaks that test and
shrinks the list to three, which loses the record of what used to be unsupported and why. Keeping
the name with a retirement note costs nothing and keeps the policy legible. A new test asserts that
no production module raises it any more, so "retired" is watched rather than assumed.

Reversibility: **costly**. Bringing the refusal back means restoring the guard, four tests and two
document rows. It is not one-way - nothing is destroyed and the git history holds the previous
form - so no decision checkpoint is inserted.
